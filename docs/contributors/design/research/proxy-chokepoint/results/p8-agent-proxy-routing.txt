================================================================================
READING NOTES — written at the run
================================================================================

1. PRIOR ART'S TWO PREDICTIONS BOTH FAILED, IN THE GOOD DIRECTION.
   `agent-proxy-support.md` named Codex (`.no_proxy()` inside its own sandbox,
   inconsistent call-site coverage) and Aider (aiohttp ignores env proxies without
   `DISABLE_AIOHTTP_TRANSPORT=True`) as the agents a forced proxy would break.
   Both took the proxy here, unmodified, with nothing but the standard variables.

   That does NOT retire the warning. The survey is version-dependent and says so;
   Codex's own-sandbox path may simply not have been entered by `codex exec`; and
   this measures the ROUTE, not a completed task. What it does mean is that the
   pessimistic assumption the round carried in is not supported by measurement,
   and a design should not be shaped around a breakage nobody has reproduced.

2. GEMINI IS UNMEASURED, NOT COMPLIANT AND NOT BROKEN. It refused to run against
   an untrusted folder in a headless environment and never opened a socket --
   `--yolo` did not change that. Scoring it either way would be inference from an
   absence. It is recorded as unmeasured, which is the only honest cell.

3. THE ONE STRUCTURAL RESULT: the sandbox's OWN Claude agent is a permanent
   background talker (`mcp-proxy.anthropic.com`, `downloads.claude.ai`, Datadog),
   so any per-agent attribution inside one sandbox is contaminated by default.
   This run excludes those hosts by name and requires a new target matching the
   agent's own provider. A cleaner design would give each agent its own sandbox,
   at four times the cost.

4. RESIDUAL LIMITATION, STATED BECAUSE IT AFFECTS ONE CELL. Attribution compares
   SETS of destination names, so a repeat request to a host some earlier window
   already saw is invisible. Aider's own LLM call to api.openai.com is exactly
   that case -- its error output proves it reached OpenAI, but the name had already
   been recorded during codex's window, so the cell is carried by aider's pypi.org
   update check instead. The verdict is unaffected; the evidence for it is weaker
   than the row makes it look, and that is worth saying rather than tidying away.
