================================================================================
READING NOTES — written at the run
================================================================================

1. THE DIRECTION SURVIVES ITS FALSIFICATION TEST. A real agent session, launched
   by the product, completed a network-dependent task with exactly one permitted
   destination and exited 0. The chokepoint was demonstrably real while it did so
   -- 18 packets hit the deny rule, and the same guest with the proxy unset could
   not reach an ordinary HTTPS host.

2. THE GUEST NEVER RESOLVED, AND NOTHING NOTICED. DNS was deliberately NOT
   permitted through the chokepoint. The session still worked, because `CONNECT
   registry.npmjs.org:443` carries a name and the proxy resolves it host-side.
   That is P6's question answered in passing and it is the Cilium inversion from
   prior-art section 1, arrived at from the other direction: under a chokepoint the
   DNS-exfil hole does not need closing because the channel does not exist.

3. THE DESTINATION LIST IS THE CLOSURE QUESTION'S EVIDENCE, and it is the first
   time this workstream has had one. Seven real destinations (example.com is this
   harness's own probe):

     api.anthropic.com                    the LLM
     mcp-proxy.anthropic.com              MCP
     downloads.claude.ai                  the agent updating ITSELF
     http-intake.logs.us5.datadoghq.com   telemetry, to a THIRD PARTY
     registry.npmjs.org                   the task's package manager
     github.com, raw.githubusercontent.com

   Two readings, and they pull in opposite directions. The set is small and
   enumerable, which is what a closed policy needs. And two of its members were
   chosen by neither the user nor the task: an update endpoint and a telemetry
   endpoint belonging to a company that is not Anthropic. A closed policy has to
   decide about those explicitly rather than inheriting them, and today nothing
   in the product would show a user they exist. That visibility is an argument
   for this direction independent of containment, and it is not one the plan
   currently makes.

4. WHAT DID NOT APPEAR: port 22. P1 saw an unasked SSH attempt to GitHub; here
   the chokepoint refused it and the task completed anyway (github.com went over
   443 instead). One session is not proof that SSH is never needed, but it is
   direct evidence that its absence is survivable, which is what P3 has to weigh.

5. ZERO PROXY ERRORS across 31 requests. The honest path needed no per-tool
   coaxing beyond the standard proxy environment variables -- for THIS agent.
   Prior art says Codex and Aider will not be so cooperative, which is P8.
