=== L7 — hook priority against docker's own chains ===
guest=172.17.0.2
-- docker's own filtering lives here --
  table ip nat
  table ip filter
  table ip6 nat
  table ip6 filter
  table ip raw
  table ip6 raw
  docker chains in the shared ip filter table: 31
  their hook priorities:
    type filter hook forward priority filter; policy accept;
    type filter hook input priority filter; policy accept;
    type filter hook output priority filter; policy accept;
  our chain at priority -10  -> egress enforced
  our chain at priority 0    -> egress enforced
  our chain at priority 10   -> egress enforced
-- the asymmetry that matters: our ACCEPT does not bind a later chain --
  a drop at a lower priority number wins outright, because the packet is gone
  before docker's chain runs. An accept only ends OUR chain; docker's rules at
  priority 0 still run afterwards and can still drop. Verify by making docker's
  table drop what ours accepts:
  ours accepts at -10, a later chain drops at 100: egress is blocked — a later chain overrode our accept
