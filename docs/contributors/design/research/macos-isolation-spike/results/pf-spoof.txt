== S1 INHERIT — A adds B's address and uses B's allowlist ==
        after 'ip addr add 192.168.64.10': 192.168.64.9/24 192.168.64.10/24 
        A -> B's allowlisted 1.0.0.1, sourced from 192.168.64.10: 000   (non-000 = INHERITED)
   PASS    S1: taking B's address did not grant B's allowlist
             READ THIS NARROWLY. pf sees the source address and its rules would permit it; what
             stops the escape is almost certainly the RETURN path — the reply is addressed to B,
             and ARP resolves it to B's interface, because B is up and answering. That is not
             enforcement, it is a collision with a live neighbour, and it says nothing about the
             case where B has exited and its address is merely stale. S3 needs no such luck.

== S3 VANISH — A takes an address in NO slot at all ==
        The pool blocks only what is IN a table. An address in no table matches no rule and meets
        pf's default. This needs no knowledge of any other sandbox, which makes it the cheap attack.
        after 'ip addr add 192.168.64.201': 192.168.64.9/24 192.168.64.201/24 
        A -> 1.0.0.1 (denied to A) sourced from the spare address: 301
        A -> 5.5.5.5 (in nobody's allowlist)  sourced from the spare address: 000
           (either non-000 = the block was escaped entirely)
   FAIL    S3: ESCAPE, and the worst one. An unlisted source address is not filtered at all.
             The pool is an allowlist of BLOCKS keyed on address, so it can only constrain
             addresses it already knows. Changing address leaves the policy behind entirely.

== S4 THE FIX — a bridge-scoped default-deny, which names no address ==
        One rule after the per-slot passes: block everything on this bridge that no slot permitted.
        If it closes S3 while leaving the matrix intact, the hazard has a one-line answer.
        rules now: 9 (one more than before)
        matrix still: A->own=301 A->B's=000 | B->own=301 B->A's=000
        spare-address escape retried: ->1.0.0.1=000  ->5.5.5.5=000   (both must be 000)
   PASS    S4: the bridge default-deny closes the escape AND preserves the matrix. One rule, no new
            grant surface, no address in it — so it costs nothing per sandbox.

== WHAT WAS NOT TRIED ==
        - MAC/ARP spoofing. Only the IP was changed. tart's --net-softnet targets the ARP layer
          specifically, and whether pf sees any of that was not examined (M1's K2 shows pf cannot
          match a MAC at all, so it almost certainly cannot).
        - --net-softnet itself. yoloAI does not pass it, so the shipped path was measured. Whether
          softnet would close S5 is untested and would be a backend change, not a pf change.
        - Raw sockets / crafted source addresses without configuring the interface. A guest with
          NET_ADMIN can do this too; only the ip-addr route was tried, which is the easy one.
        - Spoofing the GATEWAY's address, or another host on the LAN. Both are more disruptive than
          this run should be on a machine somebody uses.
        - Whether the S4 default-deny interacts with the vmnet NAT rules or with a second backend
          sharing the bridge. Measured on one bridge with two apple guests only.
