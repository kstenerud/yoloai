== WHAT WAS NOT TRIED ==
        - UDP. Every rule and every probe here is TCP. pf's stateless handling of UDP is a separate
          question and DNS rides on it.
        - Throughput cost. Linux measured allowlist sizes 1/1000/10000 and found the run-to-run
          variance larger than any difference. Nothing here measures what per-packet evaluation
          costs on pf at any allowlist size, so "it costs nothing" is a Linux result only.
        - `set state-policy if-bound`. If a floating state created elsewhere on the host can match
          this flow on the bridge, that is a second way to defeat `no state`, and if-bound would be
          the counter. Not loaded, and an anchor may well ignore it the way it ignores `set timeout`.
        - Concurrency. One sandbox, one flow. Whether a second sandbox's traffic is affected by
          these rules was measured for the stateful shape (pf-revocation-alt.txt T4) and not here.
        - Long-lived idle connections, which is where state timeouts would have mattered.
        - Whether `no state` changes anything for traffic the host TERMINATES rather than routes.
          The gateway path here is host-terminated and it is the path the revocation was measured
          on, which makes the external/NAT'd path the one with the weaker evidence.
